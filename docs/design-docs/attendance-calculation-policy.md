# 勤怠計算ポリシー設計（所定内外・深夜・休日・丸め）

**Status:** Design decided — 実装は T-03（日次労働時間区分 read-model）以降で行う。本書は設計決定のみ
**Updated:** 2026-07-04
**Scope:** 実労働時間を割増賃金計算・36協定監視の入力となる法令区分へ分類する規則の確定
**親タスク:** [attendance-domain-gap-tasks.md](../exec-plans/attendance-domain-gap-tasks.md) T-01（G1 設計）
**関連:** [work-schedule-master.md](./work-schedule-master.md) Follow-up Designs 1 の具体化

## Purpose

現行の実績値は `attendance.total_work_hours`（f64、実休憩控除後の総時間）1 本であり、
割増賃金計算に必要な区分（所定内 / 法定内残業 / 法定外残業 / 深夜 / 法定休日労働)が存在しない。
本書はこの区分の定義を 1 箇所で確定し、後続タスクの source of truth とする。

**Consumers（本書の決定を入力とするタスク）:**

| タスク | 参照する決定 |
| --- | --- |
| T-03 日次区分 read-model 実装 | Decision 1–8, 10–12 の全て（本書の実装） |
| T-06 休暇承認→勤怠反映 | Decision 9（休暇日の扱い） |
| T-07 残業申請突合 / T-08 36協定監視 | Decision 4–5, 8（法定外労働時間の定義） |
| T-09 遅刻・早退・欠勤判定 | Decision 9–10（欠勤の扱い、grace の用途限定） |
| T-13 振替休日・代休 | Decision 6, 9（法定休日の識別、休日出勤の区分） |
| T-14 給与エクスポート契約 | Decision 1（出力項目の分類体系） |

## Inputs And Existing Constraints

本書は次の既存決定を前提とし、これらを変更しない。

1. 実績時間は `attendance_correction_effective_values` 適用後（effective）の clock/break timestamp 差分から
   **整数分で直接計算**する。保存済み `total_work_hours`（f64）は入力に使わない
   （[EP-20260703-work-schedule-phase3-settlement-balance](../exec-plans/active/EP-20260703-work-schedule-phase3-settlement-balance.md) Design Decision 1）
2. 休憩は**実休憩打刻ベース**で控除する。予定休憩の自動控除はしない（同 Decision 2、
   work-schedule-master.md Weekly Pattern 節）
3. 実績の月帰属は **`work_date` 基準**。夜勤（`end_day_offset = 1`）が暦日・暦月を跨いでも
   `work_date` の属する月へ全量帰属させ、終了日で分割しない（同 Decision 10、Time Semantics）
4. raw punch timestamp は丸めず保存し、丸め後の値は派生値として扱う（Time Semantics）
5. flex の `expected_work_minutes` は flex band の最大稼働可能幅であり契約所定時間ではない。
   契約所定は `work_schedule_settlement_periods` を参照する（同 Decision 7）
6. `ResolvedWorkday` snapshot（timezone / `workday_boundary` / `day_kind` / 予定区間 / `schedule_type`）を
   予定側の入力とし、published version と locked projection の不変性には触れない

法令値（8h/日・40h/週、深夜帯、割増率の適用対象）はいずれも就業規則マスタの既定値として持ち、
ハードコードしない（Decision 11）。本書は法的助言ではなく、実値の設定責任は運用側にある。

## Decisions

### Decision 1: 区分体系 — 基本区分（partition）+ 深夜（overlay）の 2 軸

日次の実労働分（整数分）を次の**基本区分**へ重複なく分割する。

| 区分 | 意味 |
| --- | --- |
| `scheduled` 所定内 | 予定所定労働時間の範囲内の労働 |
| `statutory_within` 法定内残業 | 所定を超えるが法定労働時間（日次・週次）の範囲内の労働 |
| `statutory_excess` 法定外残業 | 法定労働時間を超える労働（時間外割増の対象） |
| `legal_holiday` 法定休日労働 | 法定休日における労働（休日割増の対象。日次・週次の法定判定から除外） |

**深夜労働（`night`）は基本区分と直交する overlay** とし、深夜帯に重なった実労働分を
別カウンタとして測定する（基本区分の分割には影響しない）。

- 採用理由: 深夜割増は他の割増と**重畳**する（法定外かつ深夜、法定休日かつ深夜）。
  partition に深夜を混ぜると組合せ爆発する（所定内深夜 / 法定外深夜 / …）。
  「基本区分 4 種 + 深夜 overlay 1 種」は給与計算の標準的な入力形と一致する
- 不採用案: 深夜を含む単一 partition（`scheduled_night` 等の直積区分）。
  T-14 給与エクスポートで結局 2 軸へ戻す変換が必要になり、二重定義になるため不採用

割増**率**の計算・金額計算は本ポリシーの対象外（給与側の関心事。Non-goals 参照）。
本ポリシーの出力は「区分ごとの分値」まで。

### Decision 2: 実績区間の導出 — effective 打刻から「実労働区間の列」を作る

区分計算の入力は、日次合計分ではなく **実労働区間（timestamp の閉開区間）の列**とする。

- 手順: effective clock_in〜clock_out の区間から、effective 休憩区間を除去し、
  残った区間列を当該 `work_date` の実労働区間とする
- 各区分の分値は区間列から導出し、合計は必ず settlement balance と同じ
  `actual_minutes`（= 総 gross − 総休憩）に一致する（consistency invariant としてテストで固定する）
- 採用理由: 深夜（Decision 3）は時間帯との交差が法令上必須であり、分量だけでは計算できない。
  区間列を唯一の中間表現にすれば、分量ベースの区分（Decision 7)と時間帯ベースの区分（深夜)が
  同じ入力から導出でき、二重計算を防げる
- 休憩の帰属: 休憩区間はそれが実際に発生した時刻で区間列から除去される。
  したがって深夜帯中の休憩は深夜分にも算入されない（自然に整合する）
- 進行中 attendance（clock_out 欠落）は実労働区間なし（全区分 0 分）として扱い、
  settlement balance の `in_progress` 扱い（Decision 11 同 EP）と整合させる

### Decision 3: 深夜の測定は暦時刻交差、帰属は `work_date` — 分割せず全量帰属

深夜分は、実労働区間列と**暦日ごとの深夜帯**（既定 22:00–翌 5:00。version snapshot の
timezone で解釈）との交差分の合計とする。求めた深夜分は**その勤務の `work_date` へ全量帰属**させる。

- 「測定は暦時刻、帰属は `work_date`」の分離により、既存決定 3（夜勤を終了日で分割しない）と
  深夜帯の暦時刻定義が両立する。例: `work_date = 7/31` の夜勤が 8/1 の 2:00 まで及ぶ場合、
  22:00–24:00 と 0:00–2:00 の計 4 時間の深夜分はすべて 7 月の実績として集計される
- 採用理由: 実績の月帰属を区分によって変えると、settlement balance・月次サマリ・CSV と
  合計が一致しなくなる。深夜「量」の正確さは暦時刻交差で担保し、「どの月の実績か」は
  既存の `work_date` 規則に一元化する
- 不採用案: 深夜分だけ暦日へ帰属させる方式。月境界の夜勤で「総労働は 7 月・深夜は 8 月」という
  分裂が起き、全ての読み取り経路で説明コストが発生するため不採用

### Decision 4: 日次法定判定 — `work_date` 単位で法定労働時間（既定 480 分）を超えた分を法定外とする

- 1 つの `work_date` に帰属する実労働分のうち、日次法定労働時間（既定 8h = 480 分）を
  超えた分を `statutory_excess` とする
- 夜勤・`workday_boundary` 前打刻を含め、**継続勤務は始業時刻が属する勤務日の労働として
  一体で判定する**（暦日で切らない）。これは行政解釈（継続勤務は始業日の労働）と
  既存の `work_date` 帰属の両方に整合する
- 超過分の特定は時系列順とする: その日の実労働区間列を先頭から累積し、累積 480 分を
  超えた時点以降の区間が法定外になる（深夜 overlay との交差計算を可能にするため、
  「どの時間帯が法定外か」を区間として保持する）

### Decision 5: 週次法定判定 — 起算曜日は設定値（既定: 日曜）、時系列累積、月跨ぎ週は両月のデータで計算

- 週は `work_date` を就業規則マスタの起算曜日（既定: 日曜。行政解釈の既定に合わせる）で
  区切って構成する。判定は `work_date` の曜日のみで行い、暦時刻は使わない
- 週内の累積対象は「日次判定（Decision 4）で法定外にならなかった実労働分」とし、
  法定休日労働（Decision 6）は累積から除外する（二重計上の防止。行政解釈と同じ順序）
- 累積が週次法定労働時間（既定 40h = 2400 分）を超えた時点以降の分を `statutory_excess` とする。
  超過分は**それが発生した日の `work_date`** に計上されるため、月帰属は自然に `work_date` 規則へ従う
- 月跨ぎ週の整合: 月次 read-model（T-03）は対象月に**重なる週の全日**（前月末・翌月頭を含む）を
  読み込んで週次判定を行い、結果のうち対象月の `work_date` の分だけを応答へ含める。
  これにより「どの月から見ても同じ日の区分が同じ値になる」ことを不変条件とし、テストで固定する
- 不採用案: 週を月内で打ち切る方式（計算は閉じるが週 40h 判定が法令上不正確になる）、
  ISO 週固定（起算曜日が就業規則で変更できない）はいずれも不採用

### Decision 6: 法定休日の識別 — 就業規則マスタの指定曜日 × 非勤務日で判定する

- 就業規則マスタに**法定休日曜日**（既定: 日曜）を持たせる。ある `work_date` が
  (a) 指定曜日に当たり、かつ (b) `ResolvedWorkday.day_kind` が非勤務
  （`scheduled_non_working_day` または `public_holiday`）である場合、その日の実労働を
  `legal_holiday` とする（全量。日次・週次の法定判定からは除外する）
- 指定曜日が勤務予定日（`scheduled_workday`）である場合は、第一増分では**通常の勤務日として
  分類**し、法定休日労働にしない。これは就業規則設定と勤務体系設定の矛盾であり、
  設定不整合の検出（anomaly 化）は follow-up とする
- 指定曜日以外の非勤務日の労働（所定休日の休日出勤）は `legal_holiday` にせず、
  Decision 4–5 の日次・週次判定に乗せる（所定は 0 分なので全量が `statutory_within` または
  `statutory_excess` になる。労基法上の「休日割増」は法定休日のみが対象という標準実務に一致）
- 採用理由: 現行スキーマに法定休日の識別子が存在しない中で、追加スキーマ最小・決定的・
  説明可能な規則はこれである。パッケージ勤怠製品の標準方式とも一致する
- 不採用案: 「週の最後の非勤務日を法定休日とみなす」動的判定は、勤務実績によって
  法定休日が事後的に動き、再計算の再現性（本設計群の中心原則）を壊すため不採用
- T-13 への申し送り: 事前振替（振替休日）が成立した場合、元の法定休日は勤務日となり
  振替先が法定休日の性質を引き継ぐ。この状態は `WorkdayOverride` だけでは表現できないため、
  T-13 で振替ペアの表現を設計する際に本 Decision の判定入力（(a)(b)）へどう介入するかを定義すること

### Decision 7: 所定内 / 法定内残業の境界 — 日次の分量比較（時間帯比較にしない）

法定外・法定休日と判定されなかった残りの実労働分を、次の分量規則で分割する。

- `scheduled`（所定内）= min(残り実労働分, その日の所定分)
- `statutory_within`（法定内残業）= 残り実労働分 − 所定内
- 「その日の所定分」は fixed スケジュールでは `ResolvedWorkday.expected_work_minutes`
  （解決時 snapshot）とする。非勤務日・休暇日は所定 0 分
- 採用理由: 所定内 / 所定外の区別は割増賃金上「量」の問題であり（所定内単価 vs 法定内残業単価）、
  時間帯の一致は要求されない。分量比較なら settlement balance と同じ日次入力で完結し、
  早出・ずれ出勤（予定 9–18 時に対して 8–17 時勤務等）でも直感に反しない
- 不採用案: 予定区間との時間帯交差で所定内を判定する方式。遅刻して残業した日に
  「所定内が減り残業が増える」という給与実務と乖離した結果になり、
  予定休憩を控除しない既存決定（Inputs 2）とも整合させにくいため不採用
- 深夜（Decision 3）だけは法令が時間帯を要求するため、唯一の時間帯ベース計算として残る

### Decision 8: flex 日の扱い — 日次・週次の法定判定から除外し、清算期間の法定総枠で判定する

- `schedule_type = flex` の日は Decision 4–5（日次 8h・週次 40h）の対象外とする。
  労基法 32 条の 3 のとおり、flex の法定外労働は**清算期間の実労働時間が法定労働時間の総枠**
  （週法定 × 清算期間暦日数 ÷ 7。分値切り捨て）**を超えた分**として清算期間単位で判定する
- flex の区分は清算期間（第一増分では月次）単位で: `scheduled` = min(実績計, 契約所定分
  `contracted_minutes_per_period`)、`statutory_excess` = max(0, 実績計 − 法定総枠)、
  `statutory_within` = 残り。日次内訳としては実労働分と深夜分（Decision 3 は flex にもそのまま適用）のみを持つ
- 深夜・法定休日は flex でも日次でそのまま適用する（法定: flex でも深夜・休日割増は免除されない）。
  法定休日労働分は清算期間の実績計から除外する（fixed と同じ二重計上防止）
- **清算残高との役割分担（二重定義の禁止）**: 契約所定分に対する過不足（残高）は
  settlement balance API の関心事のまま変更しない。本ポリシーは**法定区分**のみを追加する。
  両者は同じ入力（effective 実績・`work_date` 帰属・settlement period）を共有するが、
  出力の意味（残高 vs 法令区分）を重複させない
- 計算不可条件は settlement balance の決定を流用する: 月内に flex 日を含み、かつ
  `unresolved_days` / `version_mixed` / `not_configured` に該当する場合、その月の flex 区分は
  fail-closed で計算不可とする。fixed/flex 混在月は fixed 日の日次区分のみ計算し、
  flex 側の清算期間判定は計算不可（`not_applicable` 相当）として明示する
- 不採用案: flex にも日次 8h 判定を適用する方式（法解釈として誤り）、
  flex 混在月の按分計算（settlement balance EP と同じ理由で労務判断を要するため fail-closed）

### Decision 9: 休暇・欠勤・休日出勤の区分上の扱い（T-06 / T-09 / T-13 への入力）

- **承認済み休暇日は労働 0 分として扱い、区分集計のどの区分にも算入しない。**
  週次累積（Decision 5）・flex 清算枠（Decision 8）の「実労働時間」にも含めない
  （年休取得日は実労働時間に算入しないという標準的取り扱い）。
  休暇は「取得日数・取得分」という**別軸のカウンタ**であり、T-06 / T-14 が扱う
- 休暇承認日に実打刻がある場合、**実績を優先して通常どおり区分計算する**
  （work-schedule-master.md の「実績は予定を上書きしない」の対偶。休暇と打刻の矛盾は
  T-06 の `leave_conflict` anomaly が可視化し、どちらを正とするかは運用が修正申請等で解消する）
- **欠勤**（予定勤務日に打刻も承認済み休暇もない過去日）は労働 0 分・全区分 0 分であり、
  区分としては表現しない。「欠勤日数」は T-09 の判定結果を別軸で数える（T-14 の控除項目入力）
- **休日出勤**は Decision 6 のとおり法定休日（`legal_holiday`）と所定休日（通常判定）に二分される。
  半日単位の扱い（半休 + 半日勤務）は T-11 で休暇が分単位化された時点で、
  「所定分 = 所定 − 休暇取得分」として本 Decision を拡張する（第一増分では日単位のみ）

### Decision 10: 丸め — 第一増分は丸めなし。導入時は「派生値の再計算」で互換を保つ

- 第一増分の区分値はすべて**丸めなしの整数分**とする（settlement balance と同一方針）
- 将来丸めを導入する場合は、就業規則マスタのポリシー（単位・方向・適用段階）として追加し、
  **入力（raw punch）は不変のまま、read-model の再計算だけで丸め後の値を導出**する。
  区分値は保存しない導出値（Decision 12）なので、丸め導入は保存データの migration を伴わない
- 丸めの適用段階は「日次区分値への丸め」を第一候補とし、打刻時刻自体への丸めは採用しない
  （raw punch 不変の Time Semantics を維持）。注意書き: 労働時間の切り捨て丸めは
  労働者不利変更として法令上許されない場面が多く、既定は「丸めなし」が最も安全である
- `late_grace_minutes` / `early_leave_grace_minutes`（version 既存フィールド）は
  **遅刻・早退の判定（T-09）専用**であり、本ポリシーの区分計算・分値には一切使わない
  （work-schedule-master.md の「賃金丸めには使わない」を再確認・強化する）

### Decision 11: 法定パラメータの外部化 — 就業規則マスタ（effective-dated 単一系列）

次のパラメータを新設の就業規則マスタで管理する（テーブル追加は T-03 実装時の新規 migration）。

| パラメータ | 既定値 | 用途 |
| --- | --- | --- |
| `statutory_daily_minutes` | 480 | Decision 4 |
| `statutory_weekly_minutes` | 2400 | Decision 5, 8 |
| `night_start` / `night_end` | 22:00 / 05:00 | Decision 3 |
| `week_start_weekday` | 日曜 | Decision 5 |
| `legal_holiday_weekday` | 日曜 | Decision 6 |

- 形状は組織全体で 1 系列の effective-dated 行（`valid_from` 付き、期間重複禁止）とする。
  部署別・ユーザー別の差分は第一増分では持たない（必要になった時点で assignment 型へ拡張する）
- 対象日の区分計算はその日時点で有効な行を参照する。行が存在しない期間は fail-closed
  （区分計算不可を明示）とし、暗黙の法定値で計算しない（work_schedule_not_configured と同じ思想）。
  seed migration で既定値の初期行を投入し、既存環境が即座に計算不可にならないようにする
- 36協定の上限値（月 45h 等）は本マスタではなく T-08 の閾値マスタで別管理する
  （就業規則と協定は改定周期・所有者が異なるため）

### Decision 12: 出力形態 — 非保存の read-model、計算不可は tagged status、週跨ぎデータを内包

- 区分値は DB へ保存しない**導出値**とする（settlement balance Design Decision 6 と同一方針）。
  締め時点の固定が必要になるのは給与エクスポート契約（T-14）の設計時であり、そこで扱う
- T-03 の API 応答は settlement balance と同じ **tagged status** 形式を踏襲する:
  計算可能なら日次内訳 + 月次合計（各区分の整数分 + 深夜分）、計算不可
  （就業規則マスタ未設定期間・flex 側の計算不可条件）は 200 + status で正当な状態として返す
- 月次 read-model は月跨ぎ週（Decision 5）のために隣接月の日次データを読むが、
  応答に含めるのは対象月の `work_date` のみとする
- correction 承認で effective values が変われば区分値も変わる（導出値である以上許容する。
  締め済み月の固定は T-12 / T-14 の関心事）

## Non-goals

- 割増率・賃金額の計算（区分ごとの分値までが本ポリシーの出力。金額は給与側）
- 変形労働制（1 ヶ月・1 年単位）、事業場外みなし、裁量労働制、管理監督者の適用除外判定
- 予定休憩の自動控除（work-schedule-master.md の申し送りどおり別ポリシー）
- 36協定上限の閾値管理と監視（T-08）
- 丸めポリシーの具体実装（Decision 10 は互換方針のみ確定）
- 就業規則マスタの部署別・ユーザー別差分

## Required Test Matrix（T-03 実装時に固定すべき境界）

- 深夜: 22:00 丁度開始 / 5:00 丁度終了 / 深夜帯内の休憩 / 月末夜勤の深夜分が当月帰属
- 日次: 480 分丁度 / 481 分 / 夜勤の一体判定（暦日で切らないこと）
- 週次: 累積 2400 分丁度の跨ぎ / 日次法定外分が週累積から除外されること / 月跨ぎ週で前月末データを
  読んだ場合と翌月から見た場合で同一日の区分が一致すること / 起算曜日変更
- 法定休日: 指定曜日 × 非勤務日 / 指定曜日 × 勤務予定日（通常判定になる）/ 所定休日出勤（通常判定）/
  法定休日労働が週累積から除外されること
- flex: 清算枠丁度 / 枠超過 / fixed 混在月（fixed 日のみ計算・flex 側は計算不可明示）/ flex 日の深夜
- 休暇: 承認済み休暇日が週累積・清算枠に入らないこと / 休暇日打刻が通常区分されること
- 就業規則マスタ: 未設定期間の fail-closed / valid_from 切替日を跨ぐ週の判定
- 整合: 全区分の合計 = settlement balance と同じ actual_minutes（consistency invariant）
